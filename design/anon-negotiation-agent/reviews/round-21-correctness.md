### 問題なしとした観点（根拠と、最も危うい前提）

- 本文の上限のミドルウェア（X-85）: 宣言の 413 は下流を呼ばず、宣言なし・偽りの宣言は読んだバイト数で止まる。FastAPI は本文を読んでから依存を評価するが、その本文の読み取りで出る starlette の HTTPException を `except HTTPException: raise` で通す（`fastapi/routing.py:466`）ので、セッション・入口の枠より前に 413 になる（試験は Content-Length あり・チャンク・セッションと枠に届かないこと・ちょうど 64 KB を本物の組み立てで見ている）。読み取りの枠より外にあるので、巨大な本文の GET は数えずに断る。**最も危うい前提**は「ExceptionMiddleware の外側にあるミドルウェアが本文を読まない」こと。いまのセッションのミドルウェアは読まないが、§7 の「面談の本文をミドルウェアで伏せる」などで外側に本文を読むものを足すと、途中の 413 が 500 になる。
- 面談の寿命と同時数（C-69・X-87）: `begin`・`create` は await を挟まないので、同じ送信元から並行に来ても数え損ねない。断った `create` は置き換えるはずの状態に触れず、送信元の上限を全体の上限より先に見る。見回りの `evict_idle` は絶対の寿命も見る。LLM を待つ 60 秒の間に 3 時間を越えた状態は、待った後の `_state()`（service.py:320 と `add_statements`）が 409 にするので、外れた状態に書いて成功を返すことはない。**最も危うい前提**は「状態を延ばす書き込みが POST だけ」で、画面（interview.js）に GET の定期の読み直しが無いこと（`setInterval`・`setTimeout` は面談の画面に無いことを確認）。
- 読み取りの枠のミドルウェアの経路の選び方（C-68 の匿名 GET の部分）: 前置きはルーターと同じ復号済みの `scope["path"]` で比べるので、エンコードで外せない。FastAPI 0.141.1 の GET の経路は HEAD を 405 にする（手元で確認）ので、`method == "GET"` だけを数えても HEAD で迂回できない。窓が変われば表を捨てるのでメモリは増え続けない。断った要求は数えない。
- 決着の読み直しの止め方（C-67）: 止まるのは `settled`、待ちを使い切ったとき、札が変わったとき（選び直し・`negotiation:ended` の読み直し・操作・削除）の 3 つで、`reload` が札を進めるので鎖は 2 本にならない。読み直しの失敗はエラーを出さずに次の待ちへ進む。書きかけの要約は `h()` の `value` がプロパティなので作り直しでも残る（node の試験あり）。POST（会う・承認）は `settle` を先に通すので、返る状態は決着済みで、操作の後に待ちを始めないことは正しい。
- deploy_check（X-86・I-39・I-37・L20-8・I-40）: どの照合も、取得の失敗・形の違い・0 件・未完了を NG にし、プロジェクト番号や祖先が分からないときは許さない側に倒れる。NG の試験が項目ごとにある。

### 試験が修正を確かめているか

- 壊せば落ちる形になっている: `settled` の前後（サーバ）と読み直しの順番・止まり方（node の偽のタイマー）、64 KB の境目とチャンク・ミドルウェアの順、送信元ごとの同時 3 件と置き換え・断ったときに状態が残ること・寿命（読み取り・書き込み・3 時間・見回り）、/64 の鍵（文書 ID まで）、deploy_check の NG の各場合。
- 届いていないもの: SSE の口を「数えない」と固定している試験（欠陥 1）、見張りの試験が `/v1/demo/` の外を列挙しないこと（欠陥 1・2）、期限切れの決着の時刻（low メモ 1）、画面の再取得が枠に収まることの試験が算数だけであること（low メモ 7）。

### low のメモ（件数に数えない）

1. 期限切れで終わった交渉（フックが呼ばれない）の決着は、§6.2 の「次の見回り（最大 60 秒）」より遅い。`sweep_once` は一覧を読んだ後に `_sweep_item` で expire し、`_settle_ended` はその（expire の前の）一覧にある nid を飛ばすので、決着は次の見回り（60 秒の待ち ＋ 見回りの所要時間の後）になる。画面の読み直しは最初の読み込み（判定から 0〜2 秒後）から合計 60 秒で諦めるので、半分ほどは決着の直前に止まる（推測）。期限切れは「なし」なので段の表示は変わらず、見えるのは /me の開示台帳の段 0 の行が出ないことだけ（C-67 の破綻シナリオ 7 の残り）。`_settle_ended` で、この見回りで expire した nid を飛ばさない（`_sweep_item` の結果を集める）か、読み直しの合計を見回り 2 回分（C-67 の元の提案の 90 秒程度）にする。src/web/sweeper.py:124-129・156-158、static/stages.js:23、design.md:798。
