## 未解決

### I-1（実装時の気づき / 設計 / low）§2.4 の性質の 2 文目「外しても交渉ができなくなることはない」は、条件付きでしか成り立たない

- **根拠**: 1a の DV-05 の確認（tests/test_remove_axis.py。本人のモデルは §2.3・§5 の例の人物で、「年収 650 万以上、当直 4 回未満なら行く」）。
  - 当直の軸を外すと、二択はすべて当直 8 回（最悪値）で見せるので、この人は「行く」を 1 件も出さない。二択からの受けるアンカーは 0 件になる。
  - 残った受けるアンカーは 1 件だけ。当直に触れない自由コメント「年収 650 万以上なら、フル出社でも行く」を、§2.3 の規則で埋めたもの（当直 0 回）。
  - ほかの 5 本の軸は、この人が気にしない軸なので、外しても 3〜4 件残った。
- **破綻シナリオ**: 嫌いな軸を外した人が、その軸に触れない自由コメントを言わなければ、受けるアンカーは 0 件になる。
  - 候補者側の AI は受けられる案しか出せない（ガード）ので、何も提案できない。
  - 交渉は、相手の提案への途中確認（側ごとに 1 回）だけが頼りになり、ほぼ「なし」で終わる。
- **扱いの時期**: 面談を作る段で、ほかの実装時の気づきとまとめて設計書を直し、承認し直す（ユーザーの判断、2026-09-29）。① と ② の実装には影響しない。
- **扱いの案**（面談を作る段で決める。設計書の変更なので承認のし直しが要る）
  - 面談の確認画面（§5 の手順 6・7）で、受けるアンカーが 0 件なら「この条件を外すと、事前に受けられる組み合わせがなくなります」と示す。外すのをやめるか、二択をやり直すかを選べるようにする。
  - §2.4 の性質の 2 文目を、条件付きの書き方に直す。
- **DV-05 (2) との関係**: 代表的な面談フィクスチャ（暫定）では、6 本すべてで 1 件以上残り、テストは通っている。当直の 1 件は、自由コメント由来。

### I-2（実装時の気づき / 設計 / medium）本物の候補者の属性帯を、どこに持つかが書かれていない

- **根拠**: 1b-1 の実装で見つかった。§3.1 の `participants` と §2.7 の `counterparty` は候補者の属性帯を使う。§3.1 の `snapshots` では、求人側のルールに帯を当てはめる。しかし、帯をどこに保存し、交渉の作成時にどこから取るかが、§3.3・§3.8・§5 のどこにもない。§3.8 の `principals/{pid}` の項目にも入っていない。
- **破綻シナリオ**: 1b-1 は、交渉の作成のたびに web から帯を受け取る形で実装した。この形では、交渉ごとに違う帯を渡せる。そうすると、求人側の帯ごとのルール（例: 経験 5〜10 年なら上限 750 万）を、帯を変えながら探れてしまう。あわせて、web が帯をどこに持つかも未定のまま残る。
- **決定**（ユーザーの判断、2026-09-29）: 面談の送信（§5 の手順 9）で、帯をポリシーと一緒に金庫の `principals/{pid}` に保存する。交渉の作成時は、金庫がそこから読み、作成の要求では受け取らない。1b-1 の差し戻しで実装する。
- **設計書の直し**: §3.3 の policy の PUT、§3.8 の保存項目、§5 の手順 9 に帯を足す。I-1 とまとめて、面談の段で承認し直す。

### I-3（実装時の気づき / 設計 / low）「24 時間の評価予算」の数え方が書かれていない

- **根拠**: 1b-1 の実装で見つかった。§3.5 は「本物の依頼者ごとの 24 時間の評価予算: 160」とだけ書く。固定の窓（最初の予約から 24 時間ごとに 0 に戻す）か、直近 24 時間か、が決まっていない。
- **決定**（ユーザーの判断、2026-09-29）: 固定の窓（1b-1 の実装のまま）。
  - 窓の切り替わりの前後で、短い間に最大 2 倍（交渉 20 件分）使える。
  - 漏れる情報の上限は丸めで決まる（AC-05）ので、影響はコストだけ。
- **設計書の直し**: §3.5 に固定の窓と書く。I-1 とまとめて、面談の段で承認し直す。
