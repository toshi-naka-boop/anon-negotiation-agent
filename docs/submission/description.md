## Negocie（ネゴシエ）― 本音を預けられる転職エージェント

### 誰の、どんな課題か

転職では、「最低いくらなら受けるか」「リモートは譲れない」といった本音が、口に出されないまま消えていきます。言えば足元を見られるかもしれないし、相手にどこまで伝わるかも分からないからです。求人側も「実は年収の上限に幅がある」とは求人票に書けません。こうして、条件をすり合わせれば合意できたかもしれない機会が失われています。人間のエージェントに話しても、その本音がどこまで伝わるかは約束できません。

### 解決策

本人は、AI との面談で本音を預けます。本音はすぐに丸め（年収なら 50 万円のマス）、AI ではない決まったとおりに動くプログラム「金庫」に入れます。生の値と面談の記録は捨てます。

求職者側と求人側の 2 体の AI エージェント（Gemini と ADK）が、決まった形のメッセージ（A2A）だけで、年収・リモート・当直などの組み合わせを自分で探してすり合わせます。事前に外した条件は、交渉の途中で本人に確かめます（1 交渉 2〜3 問まで）。人間に返すのは「会う価値があるか（見込み）」と、組み合わせ 1 つだけです。合意の後は、双方が「会う」「承認」を押すごとに、匿名の職務要約、氏名と連絡先が段階的に開きます。

### 特徴

1. **決めた粗さまでしか伝わらない**: 交渉する AI は本音の数字を知りません。金庫は組み合わせを聞かれても「受けられる／受けられない／本人確認が必要」の 3 通りでしか答えません。金庫の答えをすべて見られる最悪の攻撃者でも、分かるのは年収なら 50 万円の幅までです（防御がなければ 7 手で値が特定されます）。
2. **攻撃しても漏れない**: 「攻撃してみる」の画面で、求人担当として自然文で指示を出し、架空の候補者の年収を探れます。乗っ取りの指示は受け取る前に捨てられること、AI に渡る入力に本音の数字がないこと、金庫が 3 通りでしか答えないこと（3 枚の壁）と、攻撃者が絞り込める幅（推定区間メーター）を、その場で確かめられます。
3. **運営者を信じなくても、金庫のコードは確かめられる**: 金庫は Confidential Space（TEE）で動き、保存データの鍵を使えるのは、検証済みのイメージとプロジェクトのオーナーだけです。入口の「詳しく見る: 金庫の確認(TEE)」で、attestation（実行環境の証明）と GitHub のコミットを確かめられます。

あわせて、トレースには値ではなく構造（誰が・何回・どの項目を）だけを残し、活動ログと開示台帳で、何がいつ誰に見えたかを追えます。交渉の一時停止・取消と、回数と費用の枠で、エージェントを管理します。

### 試し方（ログイン不要）

入口の先頭に製品名と 3 行の約束、その下に 3 枚のカード（求職者・求人側・セキュリティテスト）があります。おすすめの順は次のとおりです。

1. 求人側の「求人担当の画面(デモ)」で、ケース 1 を実行する
2. セキュリティテストの「攻撃してみる」で、ボタン 1 つの実演を見る
3. 入口の「詳しく見る: 金庫の確認(TEE)」で、検証の結果を見る

面談では、実際に本音を預けられます（1 画面に 1 問。データは 30 日使わなければ自動で消えます）。

### 使った技術

Cloud Run（web・agents）、Compute Engine の Confidential Space（金庫）、Gemini（Vertex AI）、Agent Development Kit（ADK）、A2A、Firestore、Cloud KMS、Workload Identity Federation

### 正直な限界

- この版の求人側は、架空の求人（自動応答）です
- 面談の間は、運営側の web が生の値を扱います
- 運営側のコードは、交渉の手を登録でき、丸め済みの条件を読めます。それでも分かるのは丸めた値までです
- TEE で確かめられるのは、動いているイメージまでです。イメージとコミットの対応は、運営者の記録です
- 自分の交渉の「求人分析」は、サンプルの数字で見せる画面のイメージです（本物の集計ではありません）
