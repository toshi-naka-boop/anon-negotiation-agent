# 画面の確認手順(AC-19)

- 対象: 設計書 `design/anon-negotiation-agent/design.md` §5(面談)・§6.1(交渉の開始とブロック)・§6.3(本人の確認)・§7(活動ログ・並べて見る画面・管理)・§8.1〜§8.4(3 枚の壁・攻撃モード・デモとリプレイ)・§9(金庫の確認(TEE)。入口の区画)・§10(画面は静的な HTML と素の JavaScript)の画面(`static/`)。完了条件は AC-02(`scripts/check_no_web_storage.sh`)と AC-19(入口の金庫の確認(TEE)は、AC-23 の画面側)。
- AC-19 の合格: 活動ログ・開示台帳の閲覧、2 つのパネルの並列表示、一時停止・取消が、すべて画面からできる。あわせて、段階開示(「会う」「承認」)・FR-39 の「最悪漏れてもここまで」「まだ隠しているもの」・推定区間メーター・防御なしのシミュレーション・二分探索の実演を、画面で確かめる(該当する行は、`/me`・`/demo`・`/attack` の表にある)。
- 画面は 3 つの場所に分かれている: **求職者**(面談・自分の交渉。青)・**求人側**(求人担当の画面(デモ)。青緑)・**セキュリティテスト**(攻撃してみる・金庫の確認(TEE)。赤)。ナビ・上部の帯・入口のカードが、その色になる。
- この文書がすること: 画面ごとに、何を操作し、何が見えれば合格かを並べる。ブラウザを動かさずに確かめられること(HTML の参照・API の経路・コードの規則・SSE)は、`uv run pytest tests/test_ui_static.py` が確かめている(末尾の「自動で確かめていること」)。

## 準備

- 画面を開く先: デプロイ済みの `web` の URL(AC-22 の確認を済ませたもの)。ローカルで確かめるときは、`uv run python scripts/serve_local.py` で開発用サーバを動かし(Firestore エミュレータ・金庫・web を 1 プロセスで起動する。http://127.0.0.1:8080。`--port` で変えられる。止めるのは Ctrl-C)、そのブラウザで開く。既定は台本のエージェントで、面談の LLM はスタブ(年収の 3 問は、答えにかかわらず「額面 620 万円」と読み取る。自由コメント・辞めた理由は何も読み取らない)なので、Gemini は呼ばない。本物の AI(Gemini)で確かめるときは `--live`(環境変数は `scripts/run_demo.py --live` と同じ。Vertex AI の設定が要る)。デプロイ済みの環境を確かめるなら、`web` の URL を開く(環境変数は `src/web/app.py` の `create_app_from_env` の説明、起動のコマンドは設計書 §10)。
- ブラウザ: 最新の Chrome(開発者ツールの Application・Console・Network を開いておく)。依頼者のクッキーは Secure なので、ローカルの http の URL は、Chrome(Chromium 系)では 127.0.0.1・localhost で受け付けられる(このパッケージの確認はここで行った)。Safari は、http の URL では受け付けない(推測。https の URL で確かめる)。
- 確かめる人: 面談の入力は、実在の値でなく、確認用の値(例: 年収 620 万円)を使う。

## 既知の限界(画面に関わるもの)

- ブロック先の企業の求人を、交渉の開始の一覧から除く(§6.1)には、金庫からブロックリストを読む口が要るが、いまは無い。一覧には出し、ブロック先の求人を選んで始めると、409(「この求人の企業は、ブロック先に入っているため、交渉を始められません。」)と出る。
- `/me` などのページの経路は、有効なクッキーがあると利用記録の更新(閲覧だけの GET を含む。§6.3)を通る。削除中(`deleting`)の依頼者は、ページそのものが 409 の JSON になる(削除が終わるまで)。
- 台本のリプレイ(`source: scripted`)は、記録した間隔が短い。本物の Gemini の記録(`run_demo.py --live --record`)に取り直すと、間隔が実際のものになる。
- デモの架空人物の「最悪漏れてもここまで / まだ隠しているもの」(設計書 §7 は、フィクスチャの生の値を見せる)は、その値を返す口がないので、`/demo` は説明だけ(上の表)。
- 開発用サーバ(`scripts/serve_local.py`)の台本のモードでは、攻撃の交渉の攻撃者も台本で、攻撃の指示文を読まない(年収の二分探索をする)。壁 1 の有効な入力のときの LLM の出力は、スタブの固定の出力(拒否は、本物の検査)。指示文に従う攻撃者・本物の LLM の出力は、`--live` で確かめる。
