# 画面の確認手順(AC-19)

- 対象: 設計書 `design/anon-negotiation-agent/design.md` §5(面談)・§6.1(交渉の開始とブロック)・§6.3(本人の確認)・§7(活動ログ・並べて見る画面・管理)・§8.1〜§8.4(3 枚の壁・攻撃モード・デモとリプレイ)・§10(画面は静的な HTML と素の JavaScript)の画面(`static/`)。完了条件は AC-02(`scripts/check_no_web_storage.sh`)と AC-19。
- AC-19 の合格: 活動ログの閲覧、2 つのパネルの並列表示、一時停止・取消が、すべて画面からできる。**開示台帳の閲覧・段階開示・FR-39 の 2 パネル・推定区間メーター・防御なしのシミュレーションは、次のパッケージ(L2)で足す。** 該当する行には「L2 で足す」と書いた。いまは、その場所に「準備中」の区画があることだけを確かめる。
- この文書がすること: 画面ごとに、何を操作し、何が見えれば合格かを並べる。ブラウザを動かさずに確かめられること(HTML の参照・API の経路・コードの規則・SSE)は、`uv run pytest tests/test_ui_static.py` が確かめている(末尾の「自動で確かめていること」)。

## 準備

- 画面を開く先: デプロイ済みの `web` の URL(AC-22 の確認を済ませたもの)。ローカルで確かめるときは、`web`・`vault`・`agents` を起動し、Firestore エミュレータにつなぐ(環境変数は `src/web/app.py` の `create_app_from_env` と `src/vault/app.py` の `create_app_from_env` の説明、起動のコマンドは設計書 §10)。本物の AI(Gemini)を呼ぶ手順(面談の年収の読み取りなど)は、その環境の Vertex AI の設定が要る。
- ブラウザ: 最新の Chrome(開発者ツールの Application・Console・Network を開いておく)。依頼者のクッキーは Secure なので、ローカルの http の URL は、Chrome(Chromium 系)では 127.0.0.1・localhost で受け付けられる(このパッケージの確認はここで行った)。Safari は、http の URL では受け付けない(推測。https の URL で確かめる)。
- 確かめる人: 面談の入力は、実在の値でなく、確認用の値(例: 年収 620 万円)を使う。

## L2 で足す確認(まとめ)

次のパッケージで画面を足したら、この文書に確認の行を足す。

- 段階開示(`/me` の `#slot-stages`・デモの `#slot-stages`): 「会う」「承認」・匿名職務要約・架空の求人(自動応答)の明示・実ユーザーの段 2 は連絡先を集めない模擬表示(§6.2。AC-14・AC-15)。
- 開示台帳(`/me` の `#slot-ledger`): 段の遷移と、途中確認の回答の閲覧(§7。FR-38)。
- 並べて見る画面(FR-39。`/me` の `#slot-fr39`・デモの `#slot-fr39`): 「最悪漏れてもここまで」(丸め済みポリシーから、表示のたびに作る)と「まだ隠しているもの」(実ユーザーは値を持たず、種類とマスだけ。デモの架空人物は生の値)の 2 つのパネルの並列表示(§7)。
- 推定区間メーターと防御なしのシミュレーション(`/attack` の `#slot-meter`・`#slot-simulation`): 「金庫の答えをすべて見られたとしても、ここまで」・画面に「シミュレーション」の明示(§8.3。AC-12)。攻撃画面が、一覧が変わるたびに `document` へ飛ばす `attack:negotiations`(`{nids}`)を聞く。`/me` は、交渉を選んだときに `negotiation:selected`(`{nid, jobId}`)、データを消したときに `negotiation:cleared` を飛ばす。

## 既知の限界(画面に関わるもの)

- ブロック先の企業の求人を、交渉の開始の一覧から除く(§6.1)には、金庫からブロックリストを読む口が要るが、いまは無い。一覧には出し、ブロック先の求人を選んで始めると、409(「この求人の企業は、ブロック先に入っているため、交渉を始められません。」)と出る。
- `/me` などのページの経路は、有効なクッキーがあると利用記録の更新(閲覧だけの GET を含む。§6.3)を通る。削除中(`deleting`)の依頼者は、ページそのものが 409 の JSON になる(削除が終わるまで)。
- 台本のリプレイ(`source: scripted`)は、記録した間隔が短い。本物の Gemini の記録(`run_demo.py --live --record`)に取り直すと、間隔が実際のものになる。

## 自動で確かめていること(参考)

- 画面のコードの規則: 保存領域に書かない(`scripts/check_no_web_storage.sh`)、文字列から HTML を作る道がない、外部の読み込み・インラインのスクリプトがない(CSP)。
- JS が呼ぶ API("GET /v1/…" の文字列)がすべて実在する経路であること。
- 画面に要る口(セッション・面談の注記・求人・デモのケース・リプレイ・SSE)と、SSE が同じ依頼者の他の操作を止めないこと。
